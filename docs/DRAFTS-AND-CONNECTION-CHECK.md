# Локальные черновики и проверка связи

## Черновики

Обычный текст сохраняется отдельно для каждого аккаунта и каждой беседы: личный/групповой чат, «Избранное», Спутник и отдельная ветка. После переключения и перезапуска интерфейса восстанавливается текст выбранной беседы. Редактирование уже отправленного сообщения использует отдельное временное поле и не заменяет обычный черновик.

Черновик удаляется после успешного ответа сервера об отправке. Во время запроса повторная отправка заблокирована, но набирать текст можно: изменённый за это время черновик остаётся. Ошибка сети не очищает поле. После успешной отложенной отправки действуют прежние проверки совпадения текста и беседы.

Данные не синхронизируются между устройствами. Они находятся в IndexedDB `quazar-drafts`, зашифрованы AES-GCM отдельным неэкспортируемым ключом локального профиля для каждого аккаунта. Контекст аккаунта и беседы связан с шифротекстом через additionalData. Ключ и текст не отправляются серверу. Это не защита от вредоносного кода внутри самого origin. Очистка данных браузера/профиля удаляет и черновики. Вложения и состояние редактирования сообщения не сохраняются.

Запись запускается при каждом изменении; очередь пропускает устаревшие версии текста. Если хранилище недоступно, текст остаётся в памяти открытого окна, а интерфейс предлагает скопировать его перед закрытием. Заметки Спутника используют собственный редактор и собственное сохранение.

## «Проверить связь»

Кнопка находится в настройках уведомлений. Открытие панели не запрашивает разрешения и не включает микрофон. Три независимые проверки запускаются пользователем:

- **Уведомление с сервера.** Через три секунды отправляется одна проба на текущее устройство. В вебе/PWA используется текущая push-подписка; в десктопе — WebSocket текущего сеанса и штатный мост системных уведомлений. Другие устройства не показывают пробу.
- **Микрофон.** Выбранный микрофон, индикаторы до/после шумоподавления и короткие подсказки. Звук не записывается в файл и не передаётся. Проверка завершается через восемь секунд, вручную или при закрытии панели. Поздно выданное разрешение и поздняя инициализация шумоподавления не оставляют дорожки активными. Во время звонка/голосовой комнаты тест отключён.
- **Звук звонка.** Штатная мелодия входящего звонка проигрывается короткое время; пользователь подтверждает, слышал ли её. Настоящий вызов не создаётся. При закрытии панели звук прекращается.

Принятие запроса сервером, принятие push-провайдером и передача уведомления операционной системе — разные состояния. Только после успешного `showNotification` клиент отправляет квитанцию. Затем пользователь отдельно подтверждает видимое получение. Ответ API сам по себе не объявляется успешной доставкой. Системный режим тишины/фокусирования может скрыть уже переданное уведомление; интерфейс предлагает проверить разрешения и фоновые ограничения.

`POST /push/diagnostics` требует входа и текущую собственную подписку либо десктопный транспорт. Лимит — три проверки в минуту на аккаунт, общий для серверных процессов. `GET /push/diagnostics/{id}` доступен только владельцу. Проба действует две минуты. Квитанция `/receipt` требует случайный одноразовый секрет из push/WS; в базе хранится хеш, в показанное уведомление секрет не попадает. При повторной квитанции результат сохраняется. Устаревшие записи очищаются при запуске следующей проверки.

Проверка push принимает HTTPS-адреса сервисов Google, Mozilla, Apple и Microsoft, проверяет публичность DNS и не следует редиректам. Неподдерживаемый провайдер получает понятный результат без сетевого запроса. Транспорт выполняется вне event loop, с коротким тайм-аутом, TTL 60 секунд и общим ограничением параллелизма. Функция не требует новых переменных окружения: для веба нужны уже настроенные VAPID-ключи. Новая таблица `connection_checks` создаётся штатным `create_all` при старте.

Источники адресов провайдеров: [Google](https://web.dev/articles/push-notifications-overview), [Apple](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [Mozilla](https://wiki.mozilla.org/Firefox/Services/).

## Проверки

- `npm test` и `npm run build` из `web`.
- `python -B -m unittest tests.test_connection_check tests.test_notification_delivery` из `backend`, с тестовой PostgreSQL.
- Из корня после сборки веба: `BROWSER_TEST_CASE=drafts-connection backend/.venv/bin/python -B desktop/test/run-device-pairing.py`. Harness создаёт отдельную временную базу, синтетические аккаунты, чаты и Звезду, а затем удаляет их. Проверяются переключение и перезагрузка черновиков, редактирование, подтверждённая/неудачная отправка, ввод во время запроса, Спутник и ветка, серверная квитанция по WebSocket и освобождение искусственного микрофона. Реальный микрофон, системные уведомления и звук в сквозном тесте не используются. Для Linux нужен `xvfb-run -a`.
