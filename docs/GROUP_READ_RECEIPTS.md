# Кто прочитал сообщение в группе

В обычных групповых чатах автор открывает список через галочки под своим сообщением или пункт «Кто прочитал» в его меню. Общий веб-интерфейс используется и в Windows/macOS-клиентах.

Список содержит отображаемое имя (либо никнейм), аватар и время первого подтверждения. Имена сортируются по общему правилу приложения: кириллица, латиница, остальные символы. Автор не включается в список получателей.

## Доступ и хранение

- `GET /chats/{chat_id}/messages/{message_id}/readers` требует действующую авторизацию, членство в чате и совпадение `sender_id` сообщения с текущим пользователем. Владельцы, администраторы и модераторы группы исключения не получают. Ответ имеет `Cache-Control: no-store` и не содержит телефонов или почты.
- Источник данных — `message_read_receipts` с уникальным ключом `(message_id, user_id)`. Таблица создаётся штатным idempotent `Base.metadata.create_all` при старте backend. Дата первого подтверждения сохраняется при повторах и чтении на нескольких устройствах.
- Подтверждение принимается только для видимого сообщения из чата, где получатель состоит. Доставка, собственные сообщения, скрытые и истёкшие сообщения не создают отметок прочтения. Удаление сообщения удаляет его отметки каскадно.
- Если получатель вышел из группы, уже сделанное подтверждение остаётся. Если автор вышел, доступ к списку и новые приватные события ему недоступны.

## Клиенты и обновление

Обычный `MessageOut` содержит только личный флаг `read_by_me`, без чужих имён или списка читателей. Новый клиент подтверждает групповое прочтение независимо от общей галочки `status`, а сервер подтверждает запись отдельным приватным `message_read_ack`. Потерянное подтверждение повторяется после восстановления соединения. Пакеты отправляются частями, чтобы не превышать серверный лимит.

Событие `message_read` отправляется только автору. Если список открыт, он перечитывается с сервера; новые прочтения не создают системных уведомлений. Чужие события, устаревшие ответы API и ответы после смены аккаунта не выводятся в окне.

До этой функции точной истории персональных подтверждений не было. Данные не восстанавливаются по общей галочке или дате вступления в группу. Для старых сообщений список может быть неполным и пополняется при чтении обновлёнными клиентами. Старые клиенты могут не присылать повторное подтверждение уже прочитанного кем-то сообщения, поэтому полный учёт требует обновления получателей. Этот предел обозначен в самом окне.

## Проверки

`tests.test_group_readers` на PostgreSQL проверяет авторский доступ, запрет владельцу/админу/постороннему, отдельные подтверждения, конкурентные устройства, первое время, выход из группы, скрытие, истечение и каскадное удаление. Веб-тесты проверяют приватность окна, сортировку, живое обновление, переподключение, ошибки и устаревшие запросы, а также независимость личного подтверждения от общей галочки.
