# Уведомления и @упоминания

Для личного чата, группы, Звезды и Спутника доступны пять режимов:

- Все сообщения — включая сообщения в ветках.
- Только упоминания — `@имя`, разрешённое `@все` и адресные группы.
- Только ответы мне — ответ на моё сообщение или в начатой мной ветке.
- Упоминания и ответы мне — любой из двух предыдущих случаев.
- Ничего — без всплывашек, звука и push; непрочитанное продолжает считаться.

По умолчанию личные чаты, группы и Звёзды уведомляют обо всех сообщениях.
Спутник наследует уровень Звезды; свой уровень Спутника имеет приоритет.
Явные старые настройки сохраняются, включая выключение. Прежнее значение API
`mentions` по-прежнему означает упоминания **и** ответы; новый `mentions_only`
означает только упоминания, `replies` — только ответы. Остальные значения —
`all` и `none`.

Временная тишина на час, восемь часов, сутки или неделю действует поверх уровня.
Временная тишина всей Звезды отключает и её Спутники. Также учитываются
«Не беспокоить» и включённое рабочее время рабочей Звезды.

## Где настроить

У чата и группы — меню «Ещё» либо профиль собеседника, пункт «Уведомления».
У Звезды — кнопка колокольчика в колонке каналов, у Спутника — в его шапке.
Настройки хранятся в `notify_settings`, общие для устройств:
`GET /users/me/notify`, `PUT /users/me/notify/{chat|star|channel}/{id}`.
Изменение рассылается событием `notify_setting`.

Общее разрешение уведомлений и звук сообщений настраиваются отдельно на каждом
устройстве. Браузерное/системное разрешение выдаёт сам пользователь кнопкой;
фоновый эффект после входа его не запрашивает.

## Доставка в веб-версии и PWA

В открытом окне в фокусе клиент показывает всплывашку и звук. Для просматриваемого
чата уведомление не дублирует сообщение на экране. Видимое, но неактивное окно
не считается прочитанным или просматриваемым Спутником.

В фоне клиент может показать системное уведомление по WebSocket. Для закрытой
или замороженной PWA сервер независимо отправляет Web Push — открытое соединение
само по себе не отменяет push. Работающее устройство подтверждает обработку
конкретного сообщения через `/push/ack`; сервер даёт ему короткое окно перед
отправкой push. Подтверждение одного устройства не подавляет уведомления других.

Оба транспорта используют тег по ID сообщения, без повторного звукового сигнала
при замене того же тега. Service worker сообщает страницам о показанном push,
чтобы запоздалый WebSocket не создавал повторную всплывашку.
Каждый полученный push показывается системным уведомлением — это необходимо
для соблюдения требований Web Push, в том числе Safari.

Подписка автоматически проверяется при входе, возвращении в окно, восстановлении
сети и смене service worker. Если ключ VAPID изменился, подписка пересоздаётся.
При выходе подписка удаляется из браузера и отвязывается от аккаунта.
Состояние включения и звук устройства сохраняются в его подписке на сервере.

Отправка push выполняется вне основного event loop, с тайм-аутом и ограничением
параллелизма. Для каждого push-провайдера создаётся отдельный набор VAPID claims.
Сообщения могут храниться у push-провайдера до суток; исчезающие сообщения —
не дольше срока жизни. У звонков и дверных приглашений короткий TTL.
Подписки с ответом 404/410 удаляются, сбой одного устройства не мешает остальным.

## Доставка в приложение для Android

Приложение для Android (2.5.0+) получает уведомления через Firebase Cloud Messaging. Сервер шлёт
их из той же `send_push_to_user`, что и web push (`backend/app/core/push.py` → `backend/app/core/fcm.py`):
те же события, тот же заголовок и текст, что показывает `sw.js`; новое уведомление того же чата
заменяет прежнее (тег). Телефоны хранятся в таблице `fcm_devices`: приложение после входа шлёт
`PUT /push/fcm {token}`, при выходе или если выключить уведомления — `POST /push/fcm/unregister`
(без входа: адрес знает только само приложение). Удалили приложение — Firebase отвечает 404 /
`UNREGISTERED`, и адрес удаляется сам.

Входящий звонок приложению 2.6.0+ уходит служебным сообщением (без `notification`): приложение само
показывает экран звонка поверх блокировки. В нём срок звонка (`ends_at_ms`) и ключ «Отклонить»
(`decline_token`, HMAC от id звонка и вызываемого) для `POST /api/calls/{id}/decline` без входа.
Когда звонок перестаёт звонить (ответили, отклонили, сбросили, таймаут), сервер шлёт в приложение
`call_cancel` (`send_app_push_to_user` — только FCM, web push так не шлём: браузер обязан показать
уведомление на каждый пуш). Приложения старше 2.6.0 получают звонок обычным уведомлением.

Ключ сервиса: JSON-ключ сервисного аккаунта Firebase в секрете GitHub `FIREBASE_SERVICE_ACCOUNT`.
Деплой кладёт его в `/opt/quazar/secrets/firebase-service-account.json` (права 600; битый ключ не
заменяет рабочий), backend читает его из `/run/quazar-secrets/` (`FIREBASE_SERVICE_ACCOUNT_FILE`).
Нет ключа — уведомления в приложение молча не отправляются. Проверка связи в настройках
работает только для web push; в приложении она подсказывает, где включить уведомления в Android.

## Звуки

Все сигналы синтезируются в браузере (Web Audio, без аудиофайлов): `web/src/notifications/sound.ts`
и `web/src/sounds/starSounds.ts`.

| Событие | Сигнал |
|---|---|
| Сообщение, напоминание, колокольчик брони | «деревянное о-оу»: две ноты маримбы вниз |
| «Скоро встреча» (за 10 минут до брони) | три колокольчика вверх |
| Входящий звонок | «калимба-капель»: арпеджио калимбы с лёгким эхом, круг 3,84 с |
| Исходящий звонок, пока не ответили | мягкие гудки 425 Гц: 0,8 с с плавными краями, круг 3,5 с |
| Звонок соединился / закончился | две ноты вверх / две ноты вниз (сброс, занято, не ответили — тоже) |
| Пропала связь в звонке или в комнате | «сонар»: тихий пинг с эхом каждые 2,5 с; в комнате — если связь не вернулась за 2 с, по возвращении — звук входа |
| Звуки Созвездия: вход, выход, стук, приглашение, запись | см. Настройки → Уведомления |

Пропущенный входящий звонок не даёт сигнала «закончился» — там уже звучал рингтон.

**Окно в фоне.** Когда окно открыто, но не в фокусе (или свёрнуто), системное уведомление
показывается беззвучным, а звучит наш сигнал — если браузер уже разрешил странице звук.
Разрешение будится на первом нажатии мышью или клавише. Пока его нет (окно только открыли и
ни разу не трогали) — звучит звук системы, как раньше. Если push от сервера уже показал это
уведомление и прозвенел, наш сигнал не играет. Для закрытой вкладки (Web Push) и закрытого
приложения на Android звучит системный звук.

## Демонстрация экрана

Пока пользователь показывает свой экран — в звонке один на один или в голосовой
комнате Созвездия, — Quazar ничего не показывает поверх: ни всплывашек, ни
системных уведомлений (в том числе в десктопном приложении), ни карточек дверей
(«зовёт», «стучится»), ни плашек-подсказок, ни окна «Это вы входите?» (уже начатую
сверку не прячем). Уже показанные системные уведомления Quazar закрываются в момент
начала показа. Звук сообщений, напоминаний и дверей остаётся по настройкам устройства.

Входящий звонок во время показа не показывается и не звонит. Если он ещё идёт, когда
показ закончился, окно звонка появляется без рингтона. Звонок, начавший звонить до
показа, замолкает, как только показ начался.

Сообщение, полученное во время показа, устройство подтверждает через `/push/ack`, чтобы
сервер не прислал ему push. Service worker перед показом любого push (кроме проверки
связи) спрашивает открытые окна сообщением `quazar-presenting?` через `MessageChannel`;
окно, которое показывает экран, отвечает `{presenting: true}`, и уведомление не
показывается. Не ответившее за 300 мс окно считается непоказывающим.
Флаг показа: `web/src/notifications/presenting.ts`.

## Упоминания, ответы и приватность

В Спутниках сервер сохраняет адресатов упоминаний; `@все` и `@here` разрешены
модераторам и выше. Примеры внутри кода не считаются упоминаниями.
В режиме ответов уведомляется также автор корня ветки, даже если эта ветка
не загружена на устройстве. Нажатие уведомления открывает нужное сообщение/ветку.
Для общего Спутника используется Звезда самого получателя.

В личных E2E-чатах текст остаётся зашифрованным. Для фильтрации упоминаний в фоне
отправитель передаёт отдельный список ID упомянутых участников; сервер ограничивает
его участниками чата. Список сохраняется и для отложенной отправки.
Текст личного сообщения в push не передаётся — только «Новое сообщение» и адрес чата.
Старые клиенты без метаданных упоминаний поддерживают push обо всех сообщениях
и ответах, но не адресные push по упоминаниям внутри шифротекста.

Для фоновых уведомлений нужны разрешение браузера/ОС, активная подписка и
настроенные VAPID-ключи. Если разрешение запрещено пользователем или системой,
приложение не может включить его автоматически.

Расчёт уровней: `backend/app/core/notify.py` и `web/src/notifications/levels.ts`.

## Непрочитанное и отметка упоминания

В чатах, Спутниках и на значках Звёзд используется общий зелёный счётчик: количество непрочитанных (до `99+`) и отдельный символ `@`, если среди них есть упоминание текущего пользователя. Упоминание не заменяет общее число. Выключенный звук/уведомления не отменяют счётчик; приглушённый режим меняет только его яркость.

Для обычных групп API списка чатов возвращает `unread_count` и `unread_mentions`, рассчитанные по персональной отметке чтения. У новых групповых сообщений цели упоминаний сохраняются как ID пользователей в `messages.mention_user_ids` (JSONB), поэтому смена никнейма не теряет адресата. Шифротекст личных сообщений сервер не разбирает. Для исторических групповых сообщений без метаданных разбираются только непрочитанные тексты по текущему никнейму. Код, метаданные превью/пересылки и служебные поля вложений не считаются упоминаниями.

После чтения, правки и удаления клиент обновляет сводку. Отметка другого участника не сбрасывает мои непрочитанные. Миграция добавляет nullable-колонку JSONB при старте приложения.
