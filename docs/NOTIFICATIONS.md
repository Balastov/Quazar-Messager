# Уведомления и @упоминания

Для личного чата, группы, Звезды и Спутника доступны пять режимов:

- Все сообщения — включая сообщения в ветках.
- Только упоминания — `@имя`, разрешённое `@все` и адресные группы.
- Только ответы мне — ответ на моё сообщение или в начатой мной ветке.
- Упоминания и ответы мне — любой из двух предыдущих случаев.
- Ничего — без всплывашек, звука и push; непрочитанное продолжает считаться.

По умолчанию личные чаты, группы и Звёзды уведомляют обо всех сообщениях.
Спутник наследует уровень Звезды; свой уровень Спутника имеет приоритет.
Явные старые настройки сохраняются, включая выключение. Прежнее значение API
`mentions` по-прежнему означает упоминания **и** ответы; новый `mentions_only`
означает только упоминания, `replies` — только ответы. Остальные значения —
`all` и `none`.

Временная тишина на час, восемь часов, сутки или неделю действует поверх уровня.
Временная тишина всей Звезды отключает и её Спутники. Также учитываются
«Не беспокоить» и включённое рабочее время рабочей Звезды.

## Где настроить

У чата и группы — меню «Ещё» либо профиль собеседника, пункт «Уведомления».
У Звезды — кнопка колокольчика в колонке каналов, у Спутника — в его шапке.
Настройки хранятся в `notify_settings`, общие для устройств:
`GET /users/me/notify`, `PUT /users/me/notify/{chat|star|channel}/{id}`.
Изменение рассылается событием `notify_setting`.

Общее разрешение уведомлений и звук сообщений настраиваются отдельно на каждом
устройстве. Браузерное/системное разрешение выдаёт сам пользователь кнопкой;
фоновый эффект после входа его не запрашивает.

## Доставка в веб-версии и PWA

В открытом окне в фокусе клиент показывает всплывашку и звук. Для просматриваемого
чата уведомление не дублирует сообщение на экране. Видимое, но неактивное окно
не считается прочитанным или просматриваемым Спутником.

В фоне клиент может показать системное уведомление по WebSocket. Для закрытой
или замороженной PWA сервер независимо отправляет Web Push — открытое соединение
само по себе не отменяет push. Работающее устройство подтверждает обработку
конкретного сообщения через `/push/ack`; сервер даёт ему короткое окно перед
отправкой push. Подтверждение одного устройства не подавляет уведомления других.

Оба транспорта используют тег по ID сообщения, без повторного звукового сигнала
при замене того же тега. Service worker сообщает страницам о показанном push,
чтобы запоздалый WebSocket не создавал повторную всплывашку.
Каждый полученный push показывается системным уведомлением — это необходимо
для соблюдения требований Web Push, в том числе Safari.

Подписка автоматически проверяется при входе, возвращении в окно, восстановлении
сети и смене service worker. Если ключ VAPID изменился, подписка пересоздаётся.
При выходе подписка удаляется из браузера и отвязывается от аккаунта.
Состояние включения и звук устройства сохраняются в его подписке на сервере.

Отправка push выполняется вне основного event loop, с тайм-аутом и ограничением
параллелизма. Для каждого push-провайдера создаётся отдельный набор VAPID claims.
Сообщения могут храниться у push-провайдера до суток; исчезающие сообщения —
не дольше срока жизни. У звонков и дверных приглашений короткий TTL.
Подписки с ответом 404/410 удаляются, сбой одного устройства не мешает остальным.

## Упоминания, ответы и приватность

В Спутниках сервер сохраняет адресатов упоминаний; `@все` и `@here` разрешены
модераторам и выше. Примеры внутри кода не считаются упоминаниями.
В режиме ответов уведомляется также автор корня ветки, даже если эта ветка
не загружена на устройстве. Нажатие уведомления открывает нужное сообщение/ветку.
Для общего Спутника используется Звезда самого получателя.

В личных E2E-чатах текст остаётся зашифрованным. Для фильтрации упоминаний в фоне
отправитель передаёт отдельный список ID упомянутых участников; сервер ограничивает
его участниками чата. Список сохраняется и для отложенной отправки.
Текст личного сообщения в push не передаётся — только «Новое сообщение» и адрес чата.
Старые клиенты без метаданных упоминаний поддерживают push обо всех сообщениях
и ответах, но не адресные push по упоминаниям внутри шифротекста.

Для фоновых уведомлений нужны разрешение браузера/ОС, активная подписка и
настроенные VAPID-ключи. Если разрешение запрещено пользователем или системой,
приложение не может включить его автоматически.

Расчёт уровней: `backend/app/core/notify.py` и `web/src/notifications/levels.ts`.
