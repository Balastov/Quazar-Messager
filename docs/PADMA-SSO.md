# Вход в Padma через Квазар

Общий документ для Padma (`QUAZAR_SSO.md`) и Квазара (`docs/PADMA-SSO.md`).
Содержание копий одинаковое; при изменении правьте обе.

## Цель

Один аккаунт для двух сервисов. Квазар — провайдер входа: он подтверждает телефон
звонком. Padma — клиент: принимает только аккаунты Квазара с подтверждённым телефоном.

- Пользователь Квазара входит в Padma кнопкой «Войти через Квазар». Если связи нет и
  номера в Padma нет, Padma создаёт ученика без учителя.
- Существующий пользователь Padma один раз входит паролем и нажимает «Привязать Квазар».
  Привязка разрешена, только если номер в Padma совпадает с подтверждённым номером в Квазаре.
- Аккаунты связываются по `sub` (id пользователя Квазара). Совпадение номера без привязки
  аккаунты не объединяет.
- Парольный вход в Padma позже отключается: сначала у привязанных, затем у всех.

## Протокол

OAuth 2.0 Authorization Code + PKCE (S256), один клиент `padma`, конфиденциальный.
OIDC-токены не выдаются: Padma получает профиль запросом `userinfo` со своего сервера.

```
Браузер → Padma  GET /api/auth/quazar/start            (или POST /api/auth/quazar/link)
Padma  → браузер 303 https://quazar-msg.ru/oauth/authorize?...
Квазар: вход / регистрация / подтверждение звонком → «Продолжить в Padma»
Квазар → браузер redirect_uri?code=…&state=…
Padma (сервер) → Квазар POST /api/oauth/token  → access_token
Padma (сервер) → Квазар GET  /api/oauth/userinfo → профиль
Padma → браузер  303 / (сессия) или 303 <страница профиля>?quazar=linked
```

## Квазар

Внешние адреса API — с префиксом `/api` (nginx отдаёт бэкенду без префикса:
маршруты FastAPI — `/oauth/...`).

### Настройки (`.env.prod`, не в git)

```dotenv
PADMA_OAUTH_CLIENT_ID=padma
PADMA_OAUTH_CLIENT_SECRET=<случайные 32+ байта>
PADMA_OAUTH_REDIRECT_URIS=https://www.padma.ru/api/auth/quazar/callback
```

Несколько адресов возврата — через запятую (например, локальный
`http://localhost:5173/api/auth/quazar/callback`). Без настроек все эндпоинты отвечают 404.

### Страница `GET /oauth/authorize` (веб-клиент)

Параметры: `response_type=code`, `client_id`, `redirect_uri`, `state`, `code_challenge`,
`code_challenge_method=S256`.

1. Проверить параметры запросом `GET /api/oauth/client?client_id=…&redirect_uri=…`
   (200 `{ "name": "Padma" }` или 400). При ошибке показать её и **никуда не перенаправлять**:
   неизвестный `redirect_uri` — открытый редирект.
2. Не вошёл — обычный вход или регистрация звонком, затем вернуться на эту страницу
   с теми же параметрами (переживают обновление вкладки).
3. Телефон не подтверждён (старый аккаунт) — предложить «Подтвердить телефон звонком»,
   затем продолжить. Без подтверждения код не выдаётся.
4. Показать: «Войти в Padma как <имя>, +7 ••• •••-••-12» и кнопки «Продолжить» / «Отмена».
   Код выдаётся только по нажатию (не автоматически).
5. «Продолжить» — `POST /api/oauth/authorize` (Bearer-сессия) с JSON
   `{ client_id, redirect_uri, state, code_challenge, code_challenge_method }` →
   200 `{ "redirect_to": "<redirect_uri>?code=…&state=…" }`, затем `location.assign`.
   «Отмена» — переход на `<redirect_uri>?error=access_denied&state=…`.
6. Страница запрещает встраивание (`frame-ancestors 'none'`), чтобы кнопку нельзя было
   нажать через чужой iframe.

### `POST /api/oauth/authorize`

Требует сессию. 403 `{ "detail": "phone_unverified" }`, если `phone_verified_at` пуст;
403 для заблокированного или неактивного. Повторно проверяет клиента и `redirect_uri`
(точное совпадение строки). `code_challenge` — 43–128 символов base64url.

Код: 32 случайных байта (base64url), в БД — только SHA-256; живёт 120 секунд;
одноразовый; привязан к `client_id`, `redirect_uri`, пользователю и `code_challenge`.
`state` не хранится, просто возвращается в адресе.

### `POST /api/oauth/token`

`application/x-www-form-urlencoded`:
`grant_type=authorization_code`, `code`, `redirect_uri`, `code_verifier`,
`client_id`, `client_secret`.

- Секрет сравнивается за постоянное время; ошибка — 401 `{ "error": "invalid_client" }`.
- Код помечается использованным атомарно. Неизвестный, просроченный, использованный код,
  другой `redirect_uri` или `BASE64URL(SHA256(code_verifier)) != code_challenge` —
  400 `{ "error": "invalid_grant" }`. Повторное использование кода отзывает выданный по нему токен.
- Ответ 200: `{ "access_token": "…", "token_type": "Bearer", "expires_in": 300 }`.
  Токен — случайная строка, в БД SHA-256, живёт 5 минут, годится только для `userinfo`.
- Ограничение частоты по IP.

### `GET /api/oauth/userinfo`

`Authorization: Bearer <access_token>`. Повторно проверяет, что пользователь активен,
не заблокирован и телефон подтверждён; иначе 401.

```json
{
  "sub": "1b9d6bcd-…",
  "phone_number": "+79991234567",
  "phone_number_verified": true,
  "given_name": "Анна",
  "family_name": "Иванова",
  "preferred_username": "anna"
}
```

`given_name` / `family_name` могут быть `null`.

### Тесты Квазара

Неизвестный клиент и `redirect_uri`; выдача кода без сессии и без подтверждённого телефона;
неверный секрет; неверный `code_verifier`; просроченный и повторный код (и отзыв токена);
`userinfo` с чужим, просроченным токеном и после блокировки пользователя.

## Padma

### Настройки (окружение сервера, не `VITE_*`)

```dotenv
QUAZAR_CLIENT_ID=padma
QUAZAR_CLIENT_SECRET=<тот же секрет>
QUAZAR_WEB_URL=https://quazar-msg.ru        # по умолчанию
QUAZAR_API_URL=https://quazar-msg.ru/api    # по умолчанию
PADMA_URL=https://www.padma.ru              # по умолчанию — первый APP_ORIGIN
```

`redirect_uri` = `PADMA_URL + /api/auth/quazar/callback`. Без `QUAZAR_CLIENT_ID` и
`QUAZAR_CLIENT_SECRET` вход через Квазар выключен и кнопки не показываются.

### Эндпоинты

- `GET /api/auth/providers` → `{ "quazar": true }` — без авторизации.
- `GET /api/auth/quazar/start` — вход: 303 на страницу Квазара.
- `POST /api/auth/quazar/link` `{ password, returnTo }` — привязка из профиля, требует
  сессию и повторный ввод пароля (неверный — 400). Ответ `{ "url": "…" }`.
- `GET /api/auth/quazar/callback?code&state` (или `error`) — 303 на `/` после входа,
  на `returnTo?quazar=linked` после привязки, при ошибке — на `/?quazar=<код>` или
  `returnTo?quazar=<код>`.

`state` и `code_verifier` — по 32 случайных байта. Запись попытки (`quazar_flows`) хранит
SHA-256 от `state`, режим, пользователя (для привязки), `returnTo` и срок 10 минут;
используется один раз. Попытка привязана к браузеру cookie `padma_oauth`
(HttpOnly, `SameSite=Lax`, `Path=/api/auth/quazar`, 10 минут): `SameSite=Strict`
не приходит при возврате с другого сайта. Поэтому привязка берёт пользователя из записи
попытки, созданной после проверки пароля, а не из сессии.

### Правила

Профиль принимается только с `phone_number_verified: true`. Номер нормализуется как
в Padma (`+7` и 10 цифр).

Вход:

| Ситуация | Результат |
|---|---|
| `sub` привязан к активному пользователю | вход; если номер в Квазаре изменился — номер Padma обновляется |
| `sub` привязан к архивному | `?quazar=archived` |
| связи нет, номер есть у пользователя Padma | `?quazar=phone_taken`: «войдите паролем и привяжите Квазар» |
| связи нет, номера нет | создаётся ученик без учителя, вход |

Привязка: номер Padma должен совпадать с номером Квазара (`?quazar=mismatch`);
`sub` не должен быть привязан к другому пользователю (`linked_other`); пользователь
не должен быть уже привязан (`already`). Любые роли можно привязать; автоматически
создаются только ученики.

После привязки телефон в Padma меняется только через Квазар: профиль и справочник
не принимают другой номер (400). У созданных через Квазар учеников нет пароля:
парольный вход для них всегда неверен.

Прочие коды ошибок в адресе: `denied` (отмена в Квазаре), `unverified`, `expired`
(попытка просрочена или из другого браузера), `failed` (Квазар недоступен или ответил ошибкой).

### Мобильное приложение

Capacitor-прототип загружает `https://www.padma.ru`; для входа во WebView нужно разрешить
переход на `quazar-msg.ru` (`server.allowNavigation`).

## Этапы

1. Вход и привязка через Квазар; пароль работает.
2. Привязанным пользователям парольный вход закрыт.
3. Пароли убираются; новых учеников администратор заводит без пароля. Привязка такого
   аккаунта по номеру при первом входе — отдельное решение (только для ни разу не входивших,
   с отметкой для администратора).
