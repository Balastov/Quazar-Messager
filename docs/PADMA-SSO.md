# Вход в Padma через Квазар

Общий документ для Padma (`QUAZAR_SSO.md`) и Квазара (`docs/PADMA-SSO.md`).
Содержание копий одинаковое; при изменении правьте обе.

## Цель

Один аккаунт для двух сервисов. Квазар — провайдер входа: он подтверждает телефон
(номера +7 — звонком, номера других стран — кодом в Telegram). Padma — клиент:
принимает только аккаунты Квазара с подтверждённым телефоном.

- Пользователь Квазара входит в Padma кнопкой «Войти через Квазар». Если связи нет и
  номера в Padma нет, Padma создаёт ученика без учителя.
- Существующий пользователь Padma один раз входит паролем и нажимает «Привязать Квазар».
  Привязка разрешена, только если номер в Padma совпадает с подтверждённым номером в Квазаре.
- Аккаунты связываются по `sub` (id пользователя Квазара). Совпадение номера без привязки
  аккаунты не объединяет.
- Парольный вход в Padma позже отключается: сначала у привязанных, затем у всех.
- Новые пользователи регистрируются только через Квазар (этап 3).

## Протокол

OAuth 2.0 Authorization Code + PKCE (S256), один клиент `padma`, конфиденциальный.
OIDC-токены не выдаются: Padma получает профиль запросом `userinfo` со своего сервера.

```
Браузер → Padma  GET /api/auth/quazar/start            (или POST /api/auth/quazar/link)
Padma  → браузер 303 https://quazar-msg.ru/oauth/authorize?...
Квазар: вход / регистрация / подтверждение телефона → «Продолжить в Padma»
Квазар → браузер redirect_uri?code=…&state=…
Padma (сервер) → Квазар POST /api/oauth/token  → access_token
Padma (сервер) → Квазар GET  /api/oauth/userinfo → профиль
Padma → браузер  303 / (сессия) или 303 <страница профиля>?quazar=linked
```

## Квазар

Внешние адреса API — с префиксом `/api` (nginx отдаёт бэкенду без префикса:
маршруты FastAPI — `/oauth/...`).

### Настройки (`.env.prod`, не в git)

```dotenv
PADMA_OAUTH_CLIENT_ID=padma
PADMA_OAUTH_CLIENT_SECRET=<случайные 32+ байта>
PADMA_OAUTH_REDIRECT_URIS=https://www.padma.ru/api/auth/quazar/callback,https://padma.ru/api/auth/quazar/callback
```

Padma открывается и с `www`, и без него, поэтому нужны оба адреса; ещё адреса — через
запятую (например, локальный `http://localhost:5173/api/auth/quazar/callback`). Без настроек все эндпоинты отвечают 404.

### Страница `GET /oauth/authorize` (веб-клиент)

Параметры: `response_type=code`, `client_id`, `redirect_uri`, `state`, `code_challenge`,
`code_challenge_method=S256`.

1. Проверить параметры запросом `GET /api/oauth/client?client_id=…&redirect_uri=…`
   (200 `{ "name": "Padma" }` или 400). При ошибке показать её и **никуда не перенаправлять**:
   неизвестный `redirect_uri` — открытый редирект.
2. Не вошёл — обычный вход или регистрация с подтверждением телефона, затем вернуться на эту страницу
   с теми же параметрами (переживают обновление вкладки).
3. Телефон не подтверждён (старый аккаунт) — предложить «Подтвердить телефон звонком»
   (номерам других стран — «кодом из Telegram»), затем продолжить. Без подтверждения код
   не выдаётся.
4. Показать: «Войти в Padma как <имя>, +7 ••• •••-••-12» (номер другой страны —
   «+33 ••• ••78»: код страны и две последние цифры) и кнопки «Продолжить» / «Отмена».
   Код выдаётся только по нажатию (не автоматически).
5. «Продолжить» — `POST /api/oauth/authorize` (Bearer-сессия) с JSON
   `{ client_id, redirect_uri, state, code_challenge, code_challenge_method }` →
   200 `{ "redirect_to": "<redirect_uri>?code=…&state=…" }`, затем `location.assign`.
   «Отмена» — переход на `<redirect_uri>?error=access_denied&state=…`.
6. Страница запрещает встраивание (`frame-ancestors 'none'`), чтобы кнопку нельзя было
   нажать через чужой iframe.

### `POST /api/oauth/authorize`

Требует сессию. 403 `{ "detail": "phone_unverified" }`, если `phone_verified_at` пуст;
403 для заблокированного или неактивного. Повторно проверяет клиента и `redirect_uri`
(точное совпадение строки). `code_challenge` — 43–128 символов base64url.

Код: 32 случайных байта (base64url), в БД — только SHA-256; живёт 120 секунд;
одноразовый; привязан к `client_id`, `redirect_uri`, пользователю и `code_challenge`.
`state` не хранится, просто возвращается в адресе.

### `POST /api/oauth/token`

`application/x-www-form-urlencoded`:
`grant_type=authorization_code`, `code`, `redirect_uri`, `code_verifier`,
`client_id`, `client_secret`.

- Секрет сравнивается за постоянное время; ошибка — 401 `{ "error": "invalid_client" }`.
- Код помечается использованным атомарно. Неизвестный, просроченный, использованный код,
  другой `redirect_uri` или `BASE64URL(SHA256(code_verifier)) != code_challenge` —
  400 `{ "error": "invalid_grant" }`. Повторное использование кода отзывает выданный по нему токен.
- Ответ 200: `{ "access_token": "…", "token_type": "Bearer", "expires_in": 300 }`.
  Токен — случайная строка, в БД SHA-256, живёт 5 минут, годится только для `userinfo`.
- Ограничение частоты по IP.

### `GET /api/oauth/userinfo`

`Authorization: Bearer <access_token>`. Повторно проверяет, что пользователь активен,
не заблокирован и телефон подтверждён; иначе 401.

```json
{
  "sub": "1b9d6bcd-…",
  "phone_number": "+79991234567",
  "phone_number_verified": true,
  "given_name": "Анна",
  "family_name": "Иванова",
  "preferred_username": "anna"
}
```

Для Padma `given_name` и `family_name` всегда заполнены (этап 3.1): без них код не
выдаётся (403 `name_required`), а если имя или фамилию стёрли уже после выдачи кода —
`/token` и `userinfo` отвечают ошибкой, как для неподтверждённого телефона.

### Тесты Квазара

Неизвестный клиент и `redirect_uri`; выдача кода без сессии и без подтверждённого телефона;
неверный секрет; неверный `code_verifier`; просроченный и повторный код (и отзыв токена);
`userinfo` с чужим, просроченным токеном и после блокировки пользователя.

## Padma

### Настройки (окружение сервера, не `VITE_*`)

```dotenv
QUAZAR_CLIENT_ID=padma
QUAZAR_CLIENT_SECRET=<тот же секрет>
QUAZAR_WEB_URL=https://quazar-msg.ru        # по умолчанию
QUAZAR_API_URL=https://quazar-msg.ru/api    # по умолчанию
PADMA_URL=https://www.padma.ru              # по умолчанию — первый APP_ORIGIN
```

`redirect_uri` = адрес сайта, на котором начат вход (`padma.ru` или `www.padma.ru`;
только из `APP_ORIGIN`), + `/api/auth/quazar/callback`: там живут cookie попытки и сессия.
Если адрес не из списка — `PADMA_URL`. Попытка хранит свой `redirect_uri` для обмена кода. Без `QUAZAR_CLIENT_ID` и
`QUAZAR_CLIENT_SECRET` вход через Квазар выключен и кнопки не показываются.

### Эндпоинты

- `GET /api/auth/providers` → `{ "quazar": true }` — без авторизации.
- `GET /api/auth/quazar/start` — вход: 303 на страницу Квазара.
- `POST /api/auth/quazar/link` `{ password, returnTo }` — привязка из профиля, требует
  сессию и повторный ввод пароля (неверный — 400). Ответ `{ "url": "…" }`.
- `GET /api/auth/quazar/callback?code&state` (или `error`) — 303 на `/` после входа,
  на `returnTo?quazar=linked` после привязки, при ошибке — на `/?quazar=<код>` или
  `returnTo?quazar=<код>`.

`state` и `code_verifier` — по 32 случайных байта. Запись попытки (`quazar_flows`) хранит
SHA-256 от `state`, режим, пользователя (для привязки), `returnTo` и срок 10 минут;
используется один раз. Попытка привязана к браузеру cookie `padma_oauth`
(HttpOnly, `SameSite=Lax`, `Path=/api/auth/quazar`, 10 минут): `SameSite=Strict`
не приходит при возврате с другого сайта. Поэтому привязка берёт пользователя из записи
попытки, созданной после проверки пароля, а не из сессии.

### Правила

Профиль принимается только с `phone_number_verified: true`. Номер нормализуется как
в Padma (`+7` и 10 цифр; с этапа 3.2 — E.164 любой страны, см. «Международные номера»).

Вход:

| Ситуация | Результат |
|---|---|
| `sub` привязан к активному пользователю | вход; если номер в Квазаре изменился — номер Padma обновляется |
| `sub` привязан к архивному | `?quazar=archived` |
| связи нет, номер есть у пользователя Padma | `?quazar=phone_taken`: «войдите паролем и привяжите Квазар» |
| связи нет, номера нет | создаётся ученик без учителя, вход |

Привязка: номер Padma должен совпадать с номером Квазара (`?quazar=mismatch`);
`sub` не должен быть привязан к другому пользователю (`linked_other`); пользователь
не должен быть уже привязан (`already`). Любые роли можно привязать; автоматически
создаются только ученики.

После привязки телефон в Padma меняется только через Квазар: профиль и справочник
не принимают другой номер (400). У созданных через Квазар учеников нет пароля:
парольный вход для них всегда неверен.

Вход по паролю у привязанного аккаунта закрыт: при верном пароле `POST /api/login`
отвечает 403 «вход только через Квазар», при неверном — обычным 401 (по ответу нельзя
узнать, привязан ли номер). Пароль привязанного аккаунта не меняется ни в профиле, ни
в справочнике (400). Привязка завершает все прежние сессии пользователя и выдаёт браузеру
новую. При обновлении до этого правила сессии уже привязанных аккаунтов один раз
завершаются (`app_meta.quazarPasswordClosed`).

Отвязка возвращает вход по паролю: связь снимается, задаётся новый пароль, все сессии
пользователя завершаются. После отвязки вход через Квазар с этим номером отвечает
`phone_taken`, пока аккаунт не привяжут заново.

- `DELETE /api/users/:id/quazar` `{ password }` — владелец или администратор
  («Отвязать Квазар» в карточке пользователя). Пароль 8–128 символов; 400, если связи нет.
- Если Квазар недоступен и войти не может сам администратор — серверный скрипт
  `server/quazarUnlink.mjs <телефон или email>` по SSH (DEPLOY.md, «Если Квазар недоступен»).

Прочие коды ошибок в адресе: `denied` (отмена в Квазаре), `unverified`, `expired`
(попытка просрочена или из другого браузера), `failed` (Квазар недоступен или ответил ошибкой).

### Мобильное приложение

Capacitor-прототип загружает `https://www.padma.ru`; для входа во WebView нужно разрешить
переход на `quazar-msg.ru` (`server.allowNavigation`).

## Этапы

1. Вход и привязка через Квазар; пароль работает. Сделано.
2. Привязанным пользователям парольный вход закрыт. Сделано.
3. Пароли убираются (план ниже, решения от 27.11.2026):
   - 3.1 Квазар: упрощённая регистрация «для Padma» и международные номера. Сделано
     27.11.2026 в `dev` (коммиты `1b4afe1`, `43e8178`, `f88f4cd`), ещё не в релизе.
   - 3.2 Padma: регистрация через Квазар, создание пользователей в Padma убирается,
     международные номера с миграцией.
   - 3.3 Padma, мягкий переход: «Сбросить пароль», баннер с крайним сроком, ссылка
     для входа, ключи доступа администраторов.
   - 3.4 Через месяц после выхода 3.3 вход по паролю закрывается для всех; затем поля
     паролей и хеши удаляются.

## Этап 3: без паролей

### Регистрация только через Квазар

Все новые пользователи Padma — и ученики, и будущие учителя и администраторы —
регистрируются сами. Аккаунты в Padma никто не создаёт: ни администратор, ни учитель.
Создание пользователя в API Padma отвечает 403, кнопки добавления в интерфейсе нет.
Администратор по-прежнему меняет роли, назначает учителя и архивирует; учителя
ученику назначает только администратор.

Сценарий:

1. Padma: на странице входа кнопка «Зарегистрироваться» → `GET /api/auth/quazar/start?register=1`
   → 303 на `/oauth/authorize?…&prompt=create`.
2. Квазар, `prompt=create`, пользователь не вошёл: упрощённая регистрация «Регистрация
   для Padma» (вместо приветственного экрана):
   - телефон → подтверждение, как в обычной регистрации, с проверкой занятости номера:
     номер +7 — звонок на показанный номер, номер другой страны — код из Telegram;
   - **фамилия и имя — обязательны**; почта и никнейм не спрашиваются;
   - «можно найти по номеру» не спрашивается: `phone_discoverable=false`;
   - пароль не задаётся.
3. Квазар показывает обычное «Войти в Padma как …» → «Продолжить» (код выдаётся только
   по нажатию, правило не меняется) → Padma создаёт ученика без учителя с фамилией
   и именем из `userinfo`.

На экране регистрации есть «Уже есть аккаунт Quazar — войти» (обычный вход, затем
возврат на эту же страницу) и «Отмена» (`?error=access_denied`).

Квазар, API регистрации: `POST /api/oauth/register` (без сессии) с JSON
`{ client_id, redirect_uri, phone, phone_verification_token, last_name, first_name }`.
Клиент и `redirect_uri` проверяются как в `/oauth/authorize`; `phone_verification_token` —
подтверждение телефона для регистрации (`/api/auth/phone-verification/…`), расходуется
вместе с созданием аккаунта. Ответ 201 `{ access_token }` — сессия Квазара в браузере,
не код для Padma. Занятый номер — 400, пустые или недопустимые имя и фамилия — 422.

`prompt=create` при уже выполненном входе в Квазар не создаёт второй аккаунт: показывается
обычное подтверждение. Если у вошедшего пользователя Квазара пусты имя или фамилия,
страница подтверждения для Padma просит их заполнить (сохраняются в профиле Квазара);
без них «Продолжить» недоступно, и `userinfo` для Padma всегда отдаёт оба поля.

Никнейм формируется Квазаром автоматически: `фамилия_имя` латиницей в нижнем регистре.

- Транслитерация: а-a б-b в-v г-g д-d е-e ё-e ж-zh з-z и-i й-y к-k л-l м-m н-n о-o п-p
  р-r с-s т-t у-u ф-f х-kh ц-ts ч-ch ш-sh щ-shch ъ, ь — пропускаются, ы-y э-e ю-yu я-ya;
  также і-i ї-yi є-ye ґ-g ў-u; латиница сохраняется (с диакритикой — без неё: é → e);
  прочие символы (пробелы, дефисы, апострофы, цифры, другие алфавиты) удаляются.
  «Иванов Пётр» → `ivanov_petr`. Если буквы дала только фамилия или только имя —
  ник из одной части, без `_`.
- Правила никнейма Квазара прежние (3–32 символа, начинается с буквы). Длинная
  фамилия обрезается так, чтобы поместились `_имя` и суффикс.
- Занят (без учёта регистра) — `ivanov_petr2`, `ivanov_petr3`, …
- Пустой результат, нарушение правил или фильтра недопустимых слов — `user_<5 случайных цифр>`
  (с той же проверкой на дубль). Пользователь может сменить никнейм в Квазаре.

Имя и фамилия в Padma берутся из Квазара при создании; дальнейшие изменения между
сервисами не синхронизируются.

### Международные номера

- Обе системы хранят номер в E.164: `+79991234567`, `+491701234567`.
- Разбор и проверка: Квазар — библиотека `phonenumbers`, Padma — `libphonenumber-js`
  (порт той же библиотеки Google). Номер без `+` разбирается как российский
  (`8 999 …` → `+7999…`). Принимается только номер, признанный действительным.
  Исключение в Квазаре: номер `+7` принимается по длине (10 цифр после кода), чтобы
  старые аккаунты не зависели от обновлений базы номеров.
- `userinfo.phone_number` — E.164 любой страны; Padma сравнивает строки E.164.
  Номер из `userinfo` уже подтверждён, Padma принимает его как есть и не проверяет
  повторно библиотекой: иначе редкий номер `+7`, принятый Квазаром, мог бы не пройти.
  Библиотекой проверяются только номера, введённые в Padma вручную, и миграция.
- Подтверждение в Квазаре (решение 27.11.2026): номера `+7` (Россия, Казахстан) —
  входящим звонком, как раньше; номера других стран — шестизначным кодом в Telegram
  через Telegram Gateway (около $0.01 за код; звонок на российский номер из-за границы
  платный для пользователя, а номер звонящего на международных маршрутах часто теряется).
  Пока на сервере Квазара не задан `TELEGRAM_GATEWAY_TOKEN`, номера других стран
  временно подтверждаются тем же входящим звонком (решение 28.11.2026): звонок
  международный за счёт пользователя, и провайдер может не увидеть номер звонящего.
- Риск: человек с иностранным номером без Telegram не подтвердит номер и не
  зарегистрируется ни в Квазаре, ни в Padma. Запасной способ (например, SMS) — позже,
  если понадобится.
- Миграция Padma (один раз, при старте, `app_meta`): перед ней — резервная копия базы;
  российские номера уже в E.164; иностранные (`+цифры` или цифры) разбираются с `+`;
  неразобранные номера остаются как есть, выводятся в журнал сервера и в список для
  администратора — их правят вручную (с таким номером вход через Квазар не совпадёт).
- Флажок «иностранный номер» в Padma убирается: формат определяется по номеру.

### Мягкий переход (3.3)

**Сбросить пароль** — `DELETE /api/users/:id/password`, владелец или администратор,
кнопка в карточке непривязанного пользователя с паролем. Пароль стирается, сессии
пользователя завершаются. Вход через Квазар с совпадающим номером привязывает такой
аккаунт: правило таблицы «Вход» меняется так —

| Ситуация | Результат |
|---|---|
| связи нет, номер у активного аккаунта **без пароля и без привязки** | привязка по номеру и вход; в карточке — «Привязан при входе через Квазар <дата>» |
| связи нет, номер у аккаунта с паролем | по-прежнему `phone_taken`: «войдите паролем и привяжите Квазар» |

Аккаунт без пароля и без привязки бывает только после сброса или отвязки, поэтому
им никто не пользуется. Аккаунты с паролем по одному номеру не объединяются.

**Отвязка** (`DELETE /api/users/:id/quazar`) пароль больше не задаёт: связь снимается,
пароль стирается, сессии завершаются; аккаунт ждёт входа через Квазар с тем же номером.

**Крайний срок.** Дата записывается в `app_meta.passwordDeadline` при первом запуске
версии 3.3: дата запуска + 1 месяц. Непривязанным пользователям с паролем Padma
показывает баннер «До <дата> привяжите Квазар: после этого вход по паролю отключится»
с кнопкой привязки. Дату видят владелец и администраторы в настройках.

**Ссылка для входа** — аварийный вход без Квазара и без пароля, когда Квазар недоступен.

- Открывает сеанс конкретного аккаунта: обычная сессия на 7 дней. Действует 15 минут,
  один раз. В БД — только SHA-256 токена. Привязку к Квазару не меняет.
- Таблица `login_links`: хеш, пользователь, кто создал, когда создана, срок, когда
  использована — это и журнал выдачи.
- `POST /api/users/:id/login-link` — владелец или администратор (кнопка «Ссылка для входа»
  в карточке пользователя). Только для аккаунтов с ролью владельца или администратора:
  войти под учеником или учителем так нельзя. Ответ `{ url }`; ссылку передают лично.
- `GET /api/auth/link?token=…` — проверяет и расходует токен, выдаёт сессию, 303 на `/`;
  неизвестный, просроченный или использованный токен — `/?login=expired`. Архивный
  аккаунт или аккаунт без нужной роли — отказ.
- Если открытого сеанса нет ни у кого — серверный скрипт по SSH
  `server/loginLink.mjs <телефон или email>` выводит такую же ссылку (для любого аккаунта).
  Он заменяет `server/quazarUnlink.mjs`.
- В конце настроек Padma владельцу и администраторам показывается мини-инструкция:
  как зайти на сервер и запустить скрипт (готовая команда, DEPLOY.md).

**Ключи доступа (passkey)** — постоянный запасной вход владельцев и администраторов без
Квазара и без пароля.

- WebAuthn; библиотеки `@simplewebauthn/server` и `@simplewebauthn/browser`.
  `rpID=padma.ru`, допустимые адреса — из `APP_ORIGIN` (`padma.ru` и `www.padma.ru`).
- В настройках: «Добавить ключ доступа» (подтверждение Touch ID, Face ID или PIN
  устройства), список ключей с названием и датой последнего входа, удаление.
  Добавить ключ может только владелец или администратор, вошедший в Padma.
- На странице входа — «Войти по ключу доступа» (ключ находит аккаунт сам, номер вводить
  не нужно). Если у пользователя больше нет роли владельца или администратора либо он
  в архиве — вход отклоняется.
- Таблица `passkeys`: id ключа, пользователь, открытый ключ, счётчик, transports, название,
  даты создания и последнего входа.
- В мобильном приложении Padma (Capacitor) ключи по умолчанию не работают: администратор
  входит по ключу в браузере.

### Окончание (3.4)

После `app_meta.passwordDeadline` сервер отклоняет любой вход по паролю (403 «Вход только
через Квазар»; при неверном пароле — 401, как сейчас), баннер исчезает. Непривязанные
аккаунты переводятся кнопкой «Сбросить пароль». Отдельным выпуском убираются форма
пароля на странице входа, поля паролей в профиле и карточке и хеши в базе.
Вход в Padma: Квазар, ключ доступа (владельцы и администраторы), ссылка для входа.

### Тесты этапа 3

Квазар (сделано): упрощённая регистрация (обязательные фамилия и имя,
`phone_discoverable=false`, никнейм: транслитерация, обрезка, дубли, запасной `user_…`),
`prompt=create` у вошедшего, дозаполнение имени, иностранные номера (подтверждение
кодом в Telegram, маскировка номера на странице подтверждения). Padma: запрет создания пользователей, миграция
номеров, привязка аккаунта без пароля по номеру, `phone_taken` у аккаунта с паролем,
сброс пароля, крайний срок, ссылка для входа (роль, срок, повтор, журнал), скрипт,
ключи доступа (регистрация, вход, потеря роли).
