# Подтверждение телефона

Способ выбирается по номеру:

- **+7 (Россия и Казахстан)** — входящий звонок через Звонок, как описано ниже.
- **Остальные страны** — шестизначный код в Telegram через
  [Telegram Gateway](https://core.telegram.org/gateway/api), см. раздел
  «Номера других стран».

Номера хранятся в E.164 (`+447911123456`). Номер без «+» читается как российский
(8…, 7…, 10 цифр), иностранный вводится с кодом страны. Номера +7 принимаются по
длине, как и раньше; остальные проверяются по базе `phonenumbers` на сервере и
`libphonenumber-js` в вебе.

## Звонок (+7)

Используется кампания Звонка типа «Звонок на проверочный номер» (`pincode_incoming`).
Пользователь сам звонит с проверяемого телефона на номер, полученный от провайдера.
Quazar опрашивает API и принимает только результат `call_status=pincode_ok` для
конкретного `call_id` и проверяемого номера. Вебхук настраивать не требуется.

## Подключение

В `/opt/quazar/.env.prod` на сервере:

```dotenv
ZVONOK_API_KEY=ключ_из_настроек_профиля
ZVONOK_CAMPAIGN_ID=идентификатор_кампании
ZVONOK_DAILY_LIMIT=500
```

Ключ не попадает в репозиторий и клиентскую сборку. Docker Compose передаёт эти
настройки бэкенду при пересоздании контейнера во время обычного деплоя.
Для локальной разработки параметры можно задать в `backend/.env`.

Новая регистрация всегда требует подтверждения и не принимает пароль.
При пустой или неполной конфигурации звонок недоступен, но обход регистрации
без подтверждения не открывается. Признак настройки доступен клиенту в
`GET /auth/providers` → `phone_verification`.

В production лимит по IP использует `X-Real-IP`, который перезаписывает штатный
host nginx. Контейнер API доступен с хоста только на 127.0.0.1. Вне такой схемы
не включайте `TRUST_PROXY_REAL_IP` и не доверяйте заголовкам посетителя.

## Пользовательский сценарий

- Новая регистрация: телефон → звонок → никнейм и остальные данные. Аккаунт
  создаётся без пароля, с заполненной датой подтверждения телефона.
- У подтверждённых пользователей вход звонком или через ранее явно привязанный
  Яндекс ID. Вход и восстановление паролем блокируются сервером, хэши сохраняются.
- Старые неподтверждённые пользователи входят прежним способом. Одного звонка
  на записанный в старом аккаунте неподтверждённый номер для входа недостаточно.
- Вход через Яндекс ID использует сохранённый идентификатор провайдера;
  совпадение телефона или почты не объединяет аккаунты. Новая привязка разрешена
  только подтверждённому аккаунту после свежего подтверждения.
- В настройках существующего аккаунта есть «Подтвердить телефон звонком».
- После подтверждения старого аккаунта прежние сессии отзываются, текущий клиент
  получает свежую. При обновлении с версии, где подтверждённому аккаунту ещё был
  доступен парольный вход, прежние сессии таких аккаунтов также отзываются.
- Неподтверждённому пользователю предложение показывается при каждой новой
  авторизации, а также раз в неделю: понедельник, 12:00 Europe/Moscow (09:00 UTC).
  Если приложение было закрыто, предложение показывается при возвращении.
  Еженедельная отметка общая для устройств, хранится на сервере; обновление
  страницы после закрытия предложения не создаёт новое напоминание.
- Смена ключей шифрования, привязка и отвязка Яндекс ID требуют свежего
  одноразового подтверждения звонком либо через уже привязанный Яндекс ID.
  Обычная проверка телефона и проверка для регистрации не подходят для этих действий.
  Параметр `force` в загрузке ключа не обходит подтверждение.
- В браузере есть кнопка `tel:`, инструкция для двух SIM и автоматическое
  обновление после звонка. Ожидающая проверка переживает обновление вкладки.
- В мобильном исходном коде добавлен тот же сценарий. Старые версии приложения
  не поддерживают вход звонком и новый порядок регистрации; подтверждённым
  пользователям потребуется новый клиент либо веб-версия. Старый парольный вход
  остаётся только у неподтверждённых аккаунтов.
- Изменение номера в профиле пока не поддерживается; подтверждение привязано
  к точному номеру и не может использоваться для другого телефона.

TOTP для пользователей с доступом к Чёрной дыре отложен на отдельный этап.

## Защита и ограничения

Проверка живёт пять минут, а её секрет хранится в БД только как SHA-256.
При регистрации подтверждение расходуется атомарно вместе с созданием аккаунта.
Повторное использование, чужой аккаунт, другой номер и просроченная проверка
отклоняются сервером. Для подтверждения текущего аккаунта нужна его сессия;
такая проверка не становится подтверждением для новой регистрации.

Провайдер может вернуть тот же `call_id` для уже запущенной заявки. Quazar
не выдаёт второму браузеру новый секрет для такого звонка: нужно вернуться
к исходной проверке либо дождаться её окончания.

Лимиты сохраняются в PostgreSQL: одна попытка на номер и назначение за минуту, до пяти
попыток на номер и двадцати на IP за час, до `ZVONOK_DAILY_LIMIT` попыток
в сутки по UTC. Учитываются и неудачные старты. Опрос провайдера — не чаще
раза в четыре секунды на проверку. Записи старше семи дней очищаются при старте
новой проверки. У пользователя сохраняется `phone_verified_at`.

Для входящей кампании реальные номера назначения возвращаются в
`data.allowed_phones_for_call`; `data.phone` — это телефон клиента.
Поле `pincode` не используется. Ключ в URL запроса статуса скрывается в HTTPX-логах;
ответы и ошибки провайдера не передаются клиенту целиком.

Основные источники: [API Звонка](https://api.zvonok.com/),
[документация V1](https://api-docs.zvonok.com/).

## Номера других стран: код в Telegram

Звонок на российский номер из-за границы — международный вызов за счёт
пользователя, а номер звонящего на международных маршрутах часто теряется.
Поэтому номера не на +7 подтверждаются кодом в Telegram.

```dotenv
TELEGRAM_GATEWAY_TOKEN=токен_из_gateway.telegram.org
TELEGRAM_GATEWAY_SENDER=          # необязательно: верифицированный канал-отправитель
TELEGRAM_GATEWAY_DAILY_LIMIT=300
```

Без токена иностранные номера получают понятный отказ (503), а регистрация
без подтверждения по-прежнему закрыта. Баланс Gateway пополняется заранее
(через Fragment); код стоит около $0.01, недоставленный за 5 минут не оплачивается.

- Код генерирует Quazar и передаёт в `sendVerificationMessage` с `ttl=300`.
  В БД хранится только HMAC кода с секретом браузера (`code_hash`), так что
  утечка таблицы не позволяет подобрать код.
- Код вводится в том же окне; клиент шлёт его в тот же `…/status` полем `code`.
  Пять неверных попыток — проверка закрывается (`failed`).
- После верного кода Quazar в фоне сообщает его Gateway
  (`checkVerificationStatus`) — только для статистики, на решение это не влияет.
- Отказ Gateway по самому номеру (нет Telegram и т. п.) показывается
  пользователю; ошибки токена, баланса и сети — как временная недоступность.
- Лимиты те же, что у звонков (минута между попытками, 5 на номер и 20 на IP
  в час), плюс собственный `TELEGRAM_GATEWAY_DAILY_LIMIT` в сутки.
- Ответ API содержит `method`: `call` или `telegram`.
- В телефонной книге номер без кода страны читается по стране владельца, а
  если не разбирается — как российский.
- Мобильный клиент на React Native (`mobile/`) иностранные номера пока не
  поддерживает; приложения для Android и iOS — обёртки веб-клиента и поддерживают.
