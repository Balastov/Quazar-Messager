# Подтверждение телефона звонком

Используется кампания Звонка типа «Звонок на проверочный номер» (`pincode_incoming`).
Пользователь сам звонит с проверяемого телефона на номер, полученный от провайдера.
Quazar опрашивает API и принимает только результат `call_status=pincode_ok` для
конкретного `call_id` и проверяемого номера. Вебхук настраивать не требуется.

## Подключение

В `/opt/quazar/.env.prod` на сервере:

```dotenv
ZVONOK_API_KEY=ключ_из_настроек_профиля
ZVONOK_CAMPAIGN_ID=идентификатор_кампании
ZVONOK_DAILY_LIMIT=500
```

Ключ не попадает в репозиторий и клиентскую сборку. Docker Compose передаёт эти
настройки бэкенду при пересоздании контейнера во время обычного деплоя.
Для локальной разработки параметры можно задать в `backend/.env`.

Если ключ и кампания пусты, проверка выключена. Если задан хотя бы один параметр,
новая регистрация требует подтверждения; неполная конфигурация или ошибка
провайдера не открывают обход проверки. Признак доступен клиенту в
`GET /auth/providers` → `phone_verification`.

В production лимит по IP использует `X-Real-IP`, который перезаписывает штатный
host nginx. Контейнер API доступен с хоста только на 127.0.0.1. Вне такой схемы
не включайте `TRUST_PROXY_REAL_IP` и не доверяйте заголовкам посетителя.

## Пользовательский сценарий

- Новая регистрация по паролю и через Яндекс ID требует подтверждения номера.
- Вход существующих пользователей остаётся доступным без новой проверки.
- В настройках существующего аккаунта есть «Подтвердить телефон звонком».
- В браузере есть кнопка `tel:`, инструкция для двух SIM и автоматическое
  обновление после звонка. Ожидающая проверка переживает обновление вкладки.
- В мобильном исходном коде добавлен тот же сценарий. Старые версии приложения
  не смогут завершить новую регистрацию на сервере с включённой проверкой;
  можно зарегистрироваться в веб-версии и войти в прежнем приложении.
- Изменение номера в профиле пока не поддерживается; подтверждение привязано
  к точному номеру и не может использоваться для другого телефона.

## Защита и ограничения

Проверка живёт пять минут, а её секрет хранится в БД только как SHA-256.
При регистрации подтверждение расходуется атомарно вместе с созданием аккаунта.
Повторное использование, чужой аккаунт, другой номер и просроченная проверка
отклоняются сервером. Для подтверждения текущего аккаунта нужна его сессия;
такая проверка не становится подтверждением для новой регистрации.

Провайдер может вернуть тот же `call_id` для уже запущенной заявки. Quazar
не выдаёт второму браузеру новый секрет для такого звонка: нужно вернуться
к исходной проверке либо дождаться её окончания.

Лимиты сохраняются в PostgreSQL: одна попытка на номер за минуту, до пяти
попыток на номер и двадцати на IP за час, до `ZVONOK_DAILY_LIMIT` попыток
в сутки по UTC. Учитываются и неудачные старты. Опрос провайдера — не чаще
раза в четыре секунды на проверку. Записи старше семи дней очищаются при старте
новой проверки. У пользователя сохраняется `phone_verified_at`.

Для входящей кампании реальные номера назначения возвращаются в
`data.allowed_phones_for_call`; `data.phone` — это телефон клиента.
Поле `pincode` не используется. Ключ в URL запроса статуса скрывается в HTTPX-логах;
ответы и ошибки провайдера не передаются клиенту целиком.

Основные источники: [API Звонка](https://api.zvonok.com/),
[документация V1](https://api-docs.zvonok.com/).
