# Новости обновлений

`Quazar_news_bot` — отдельный официальный аккаунт с личным новостным чатом для каждого пользователя. Это публичные новости продукта, без E2E. Ответы, вложения и отложенная отправка в этот чат запрещены; для вопросов остаётся «Обратная связь» и `Quazar_Admin_bot`. Боты идентифицируются раздельно по служебному номеру, поэтому новости не попадают в обращения поддержки.

После успешного production-деплоя `remote-deploy.sh` сохраняет текст новости **черновиком** через `python -m app.release_news`. До этого проверяются доступность обновлённых API и веба и совпадение версии описания с `web/package.json`. Никому ничего не отправляется: суперпользователи получают от news_bot сообщение «Готов текст новости…», а на «Чёрной дыре» появляется отметка. Публикация установщиков сама по себе не запускает вторую рассылку: один номер версии — одно сообщение.

## Одобрение в «Чёрной дыре»

«Чёрная дыра» → «Новости»: заголовок и пункты можно править, переставлять, добавлять и удалять (до 20 пунктов по 400 символов, заголовок до 100), рядом — предпросмотр сообщения. «Отправить себе на пробу» присылает текст из редактора только вам. «Опубликовать» сохраняет правки и снимает список получателей на этот момент; после этого текст не меняется. «Не публиковать» — для технических выпусков: такая новость не уйдёт и не войдёт в следующую.

Если вышла новая версия, а черновик прежней ещё не одобрен, черновики объединяются в один — под номером новой версии, с пунктами обеих (правки прежнего черновика сохраняются). Прежний получает статус «объединена». Публикуется ровно тот текст, который видел одобряющий: каждая правка увеличивает ревизию, и устаревшая форма получает «текст успели изменить». Повторный деплой той же версии обновляет только черновик, который ещё никто не правил.

Та же очередь `news_notices` доставляет личные сообщения от news_bot одному человеку (напоминания о черновике, пробная отправка, окончание пробного Premium); повторы с тем же ключом не отправляются.

При подготовке каждого релиза обновляйте `deploy/release-notes.json` вместе с номером приложения. В нём нужны `version`, короткий `title` и от одного до восьми пунктов `changes`. Пишите, что теперь доступно пользователю или какая его проблема исправлена; внутренние имена файлов, API, миграции и номера задач оставляйте в техническом changelog. Например, для ближайшего релиза подходят «Фото профиля после замены сразу обновляется» и «Об обновлениях Quazar теперь рассказывает отдельный официальный бот».

Проверка и предварительный просмотр сообщения:

```sh
python3 deploy/scripts/validate-release-notes.py
```

Без подходящего описания выкладка останавливается до пересборки контейнеров. Если релиз содержит десктопные изменения, сначала публикуются проверенные установщики, затем сайт и новости о полном выпуске.

Очередь создаёт снимок всех зарегистрированных на этот момент обычных аккаунтов, включая временно заблокированные; служебные аккаунты исключаются. Заблокированным не отправляются push и события, но сообщение останется в их чате. Зарегистрировавшиеся позже получат новости со следующего релиза. История до 0.20.3 включительно не рассылается при включении функции.

Фоновый планировщик обрабатывает очередь небольшими порциями. Сообщение и ссылка на него в очереди фиксируются одной транзакцией. После сбоя повторная обработка использует тот же ID сообщения; уведомления применяют обычные фильтры и тот же тег сообщения. Чат хранится отдельно для каждого пользователя: списка получателей и чужой переписки в нём нет.

Повторный запуск с тем же номером не отправляет новости ещё раз и не включает новых пользователей в старый выпуск. Опубликованный текст повторный деплой не меняет; исправленный анонс должен относиться к новой версии. Откат на более старый номер также не вызывает новую рассылку. В ходе разработки используются только тестовые пользователи; настоящая рассылка начнётся с ближайшего релиза после 0.20.3.
