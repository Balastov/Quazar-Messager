# Голос на Планетах (LiveKit)

Голосовые каналы Созвездия работают через медиасервер **LiveKit** (SFU): каждый участник
отправляет свой голос один раз на сервер, сервер раздаёт его остальным. Сквозного шифрования
в каналах Созвездия нет.

## Как устроено

| Часть | Где | Что делает |
|---|---|---|
| `livekit` (docker, profile `voice`) | `docker-compose.prod.yml` | медиасервер, образ `livekit/livekit-server:v1.13.7` |
| `/livekit/` в системном nginx | добавляется `remote-deploy.sh` | сигналинг (WebSocket) → `127.0.0.1:7880` |
| `7882/udp`, `7881/tcp` | открываются в фаерволе вручную | сам голос (UDP), запасной путь по TCP |
| coturn `3478` | уже настроен | ретранслятор для клиентов за строгим NAT |
| бэкенд | `app/api/voice.py`, `app/core/livekit.py`, `app/core/voice.py` | токены входа, вместимость, модерация, «кто где сидит» по вебхукам |

Комнаты создаёт только бэкенд (`auto_create: false`); потолок — 25 человек на Планету,
вместимость конкретной Планеты проверяет бэкенд при выдаче токена (токен живёт 2 минуты).

## Показ экрана

На Планете экран показывает не больше одного человека; показать может любой участник, а
остановить чужой показ — модератор, админ и владелец (у тех, кто ниже рангом).

- Токен входа разрешает публиковать **только микрофон** (`canPublishSources: ["microphone"]`).
- «Показать экран» → `POST /stars/{id}/planets/{id}/screen`: бэкенд занимает слот и через
  `UpdateParticipant` добавляет участнику источники `SCREEN_SHARE`, `SCREEN_SHARE_AUDIO`.
  Слот занят — `409 «Сейчас экран показывает …»`.
- Закончить: `DELETE …/screen` (сам), `POST …/voice/{user_id}/screen/stop` (модератор). Бэкенд
  отзывает источник — LiveKit сам снимает трек экрана у всех.
- Нажали «Остановить показ» в браузере или вышли с Планеты — слот освобождают вебхуки
  `track_unpublished` / `participant_left`.
- Выключение микрофона модератором убирает только источник `MICROPHONE` — показ экрана идёт дальше.

Показывать можно из Chrome, Edge, Firefox и Safari на компьютере; звук вкладки — только Chrome
и Edge. С телефона показать экран нельзя (браузеры не дают), смотреть — можно. Отдельной
настройки сервера не нужно: видео идёт тем же путём, что и голос. Трафик: около 1,5–3 Мбит/с
на каждого зрителя (1080p, 15 к/с); зрителям с маленьким окном LiveKit отдаёт слой поменьше.

## Названия и звуки

В игровых Звёздах голосовые каналы — **Планеты** («Посетить Планету» / «Покинуть Планету»),
в рабочих — **Комнаты** («Войти в Комнату» / «Выйти из Комнаты»). Все формы слов —
`web/src/components/constellation/words.ts` (`roomWords`, `placeNouns`), на сервере —
`enter_words` в `app/api/doors.py`.

Звуки — один мягкий набор для всех Звёзд, синтез в браузере (`web/src/sounds/starSounds.ts`,
Web Audio, без файлов). Выключаются в Настройках → «Звуки Созвездия», там же можно прослушать:

| Событие | Звук |
|---|---|
| Я вошёл / вышел | мягкий аккорд вверх с «воздухом» / те же ноты вниз |
| Кто-то вошёл / вышел | пузырёк вверх / вниз |
| Стучатся (слышит тот, кто впускает) | два мягких касания «тук-тук» |
| Меня зовут (в Звезду, на Планету, в Комнату) | вокзальный «дин-дон-дан» |

## «Только слушать»

Настройка Планеты (галочка в её настройках, нужно право управлять каналами): микрофоны там не
используются вообще — браузер их даже не запрашивает, индикатор микрофона не загорается.

- Токен входа на такую Планету не разрешает публиковать ничего (`canPublish: false`);
  показ экрана по-прежнему выдаётся через слот.
- Переключили режим, пока люди внутри, — бэкенд сразу меняет права всем (`voice.set_listen_only`):
  клиенты освобождают микрофон, а когда режим выключают — берут его снова, выключенным.
- Выключение микрофона модератором здесь ни на что не влияет.

## Что делает деплой автоматически

`deploy/scripts/render-livekit-config.sh`:
1. если в `.env.prod` нет `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` — генерирует их (один раз);
2. собирает `deploy/livekit/livekit.yaml` (в git не попадает): публичный IP из `TURN_EXTERNAL_IP`,
   TURN из `WEBRTC_TURN_*`.

Если шаг не удался, сайт деплоится без голоса, а в логе деплоя будет `WARN: LiveKit config failed`.

## Что нужно сделать руками (один раз)

Открыть порты **7881/tcp** и **7882/udp**:
- в панели хостинга (группа безопасности / фаервол облака);
- в фаерволе самого сервера, если он включён:

```bash
sudo ufw status            # если "Status: active":
sudo ufw allow 7881/tcp
sudo ufw allow 7882/udp
```

## Проверка

```bash
curl -s https://quazar-msg.ru/livekit/          # должно ответить OK
cd /opt/quazar && docker compose -f docker-compose.prod.yml --env-file .env.prod --profile voice ps livekit
docker compose -f docker-compose.prod.yml --env-file .env.prod --profile voice logs --tail=50 livekit
```

С компьютера (не с сервера) — что UDP-порт доступен извне, проще всего проверить делом:
зайти на Планету с двух устройств из разных сетей (например, телефон через мобильный интернет).

## Если не слышно друг друга

- В браузере видно «Подключаемся…» и ошибка — порты 7881/7882 закрыты в панели хостинга.
- Подключились, но тишина — нажмите «Нажмите, чтобы слышать собеседников» (браузер блокирует
  звук без нажатия) и проверьте, что у собеседника не выключен микрофон.
- Ошибка «Голосовая связь на Планетах пока не настроена на сервере» — в `.env.prod` нет ключей
  LiveKit; смотрите лог деплоя.
